# Hive 프로젝트 설정과 지식 분리 검토

검토일: 2026-11-04. 실행 환경: 로컬 Codex·Windows·PowerShell. 범위: 현재 공략 프로젝트의 Hive 설정, 기존 세 대화의 사용자 선호, 전역 지식 쓰기 방지. 게임과 화면을 수정하는 작업은 아니다.

## 저장 결과

- 한국어 안내·한국어 위키를 켠 프로젝트 설정을 CLI로 적용했다. 사용자에게 보이고 입력할 수 있는 Codex 터미널을 사용했다.
- 사용자가 요청한 로컬 지식의 정본은 [프로젝트 전용 사용자 지식](knowledge/README.md)이다. 게임·편성 16개, 공략 작성 16개, 화면 사용 24개로 총 56개 규칙을 정리했다.
- 생성된 Hive 위키를 등록한 것처럼 수작업으로 꾸미지 않았다. 위 56개는 **일반 Markdown 지식**이며 Hive의 정본 등록·검색 색인 등록 완료가 아니다.
- 세 대화는 도구가 반환한 마지막 페이지까지 읽었다. 사용자 메시지 107개에는 공통 이력이 포함되어 있으며 식별자 중복 제거 뒤 51개다. 현재 설정 요청을 별도 출처 S52로 남겼다.
- 대화 원문, 숨은 추론, 명령 출력, 임시 첨부 경로는 지식으로 저장하지 않았다. 현재 부대 수치는 기존 진행 기록의 영역으로 남겼다.

## 전역 저장소에 대한 실제 처리

1. 설정에서 전역 공유 허용 지식 종류를 빈 목록으로 두었다. 선택 기능·후크는 추가 설치하지 않았다.
2. 적용 전 전역 지식 정본 642개 파일과 색인 관련 2개 파일의 해시를 확인했다. 해시는 파일 내용이 달라졌는지 비교하는 값이다.
3. 설정 과정에서 프로젝트의 빈 비공개 컬렉션이 등록되어 전역 공유 색인과 생성 정보 파일이 갱신됐다. 따라서 ‘전역 저장소 전체가 처음부터 읽기 전용으로 유지됐다’고 주장하지 않는다.
4. Hive 0.14가 현재 프로젝트의 로컬 색인만 사용하는 경로를 거부하는 것을 확인했다. 정확한 이유는 `project-local SQLite is supported only for authenticated Hive 0.7 or earlier; use --user-root`였다.
5. 선호 지식은 Hive 등록 명령에 넘기지 않았다. 빈 컬렉션을 CLI의 현재 작업용 일회 승인으로 분리했고 결과는 `hive.knowledge-collection-detached`였다. 승인 토큰은 지식 문서에 보관하지 않았다.
6. 이후 프로젝트 지식은 `notes/knowledge/` 파일로 읽고 갱신한다. 전역 저장소는 필요한 정본을 읽기만 하도록 `AGENTS.md`에 명시했다. 전역 조회를 핑계로 프로젝트 내용을 색인에 등록하지 않는다.

분리 후 추가 Hive 명령과 다른 동시 작업이 이어지는 동안 컬렉션이 다시 `attached`가 된 것을 발견했다. 세션 명령 자체가 원인인지, 다른 동시 작업이 원인인지는 확인하지 못했다. 빈 컬렉션이라 지식 내용은 여전히 0개였다. 일반 작업에서 Hive 명령을 자동 실행하지 않도록 범위를 제한했고, 이번 세션 예약을 닫은 뒤 마지막으로 연결을 다시 해제했다. 최종 해제 뒤의 검사는 Hive CLI를 쓰지 않는 읽기 전용 파일·SQLite 조회로 한다.

전역 정본 검사 중 다른 내용의 새 사용자 지식 파일 1개도 발견했다. 기존 642개는 내용이 그대로였으며 새 파일은 이번 프로젝트 관련 표식이 없었다. 이 세션에서는 전역 지식 기록 명령을 실행하지 않았고 그 파일을 수정·삭제하지 않았다. 동시 작업이 있으므로 전역 저장소 전체의 무변경이나 새 파일의 작성 주체는 확정하지 않는다.

## 이후 작업

- `notes/knowledge/README.md`에서 관련 문서를 읽고 `rg`로 검색한다. 이 조회는 파일 검색이며 Hive 검색으로 표현하지 않는다.
- 전역 `remember`·`ingest`·`scan --apply`·`promote`·`refresh`·`index rebuild`·동기화를 이 프로젝트 내용에 적용하지 않는다.
- 실제 전역 지식 컬렉션을 다시 연결하지 않는다. Hive 재설정·갱신이 필요하면 먼저 이 분리 상태를 재확인한다.
- 일반 작업에서는 Hive 세션·한국어 검사 등의 자동 CLI 호출도 하지 않는다. 공유 저장소의 재연결 원인을 확정하지 못했으므로 파일 조회·편집과 자체 문서 연결 확인을 사용한다.
- 이 보호는 설정·연결 해제·명시 지침의 조합이다. 운영체제의 전역 쓰기 권한을 바꾼 것은 아니다.
