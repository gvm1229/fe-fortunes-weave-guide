# 체크리스트 · 실행 시점과 선행 조건

2026-11-04 순서 교정 기록이다. 현재 레다의 첫 보관과 키릭·네이선 안내는 2부 1장과 2~3장에 있다. [현재 진행 순서와 던전 조건](sequential-routes-apply-review.md)

**축복 준비 → 새1장 → 지원 준비 → 영입 → 병종 판단 → 종료 전 점검 → 완료 → 보상 → 다음 루트 준비** 순서로 정리했다.

## 네 루트의 시작

| 루트 | 맨 위 블록 | 그다음 |
|---|---|---|
| 세오도라 | 이미 구매한13개 축복 확인 | 이월·옛2부 보류·새1장 선택 |
| 레다 | 가호 인계와 추가 축복 | 새1장 선택·첫 전투 전 경험치 설정 |
| 디트리히 | 가호 인계와 추가 축복 | 새1장 선택·첫 전투 전 경험치 설정 |
| 카이 | 가호 인계와 추가 축복 | 새1장 선택·첫 전투 전 경험치 설정 |

이전 루트 마지막 체크에서 다음 루트1장을 먼저 시작하지 않는다. 방첨탑에 저장한 뒤 다음 개인화 탭의 시작 전 축복부터 확인한다. 이미 산 단계·실제 파편·미수령 보상의 구분은 유지한다.

## 영입과 시험 준비

| 루트 | 이오800G 준비·교섭 | 알렉산드라 영입 직후 |
|---|---|---|
| 세오도라 | 기본 동선11장 점검, 명성10·지원3 | 8장 이후, 명성6·지원1 |
| 레다 | 기본 동선7장, 명성6·지원1 | 명성10·지원3을 확인하는11장 |
| 디트리히 | 4장 자유행동, 명성3·지원2 | 7장 이후, 명성8·지원3 |
| 카이 | 기본 동선10장, 명성10·지원3 | 명성7·지원2를 확인하는7장 |

이는 현재 루트 동선의 확인 위치다. 명성·지원 조건이 먼저 충족됐으면 그날 교섭 직전에800G를 준비한다. 조건 충족 후에도 표의 장까지 무조건 기다리라는 제한이 아니다. 세오도라 알렉산드라의8장 이후처럼 이야기상 제한이 있는 경우는 그대로 따른다.

- 이오의 먼 훗날 영입비를1장이나3장부터 체크시키지 않는다. 세오도라4~10장·레다4~6장·카이4~9장의 이오 선적립800G도 장별 골드 표에서 뺐다. 디트리히는 교섭 가능한4장 바로 앞에 비용 준비를 둔다.
- 지원을 올리는 작업은 영입 전에 필요하므로 기존 주간 식사·첫 선물 안내를 유지한다. 지원 준비와 실제 영입금 지급을 같은 시점으로 강제로 묶지 않는다.
- 알렉산드라의 상급 시험 보류는 네 루트 모두 실제 영입 체크 바로 다음 줄이다. 천익병을 유지한다. 비탑승 중급 자격·이오의 같은 등급 비기병 준비는 영입 뒤12장 종료 전 점검에서 확인한다.
- 처음 화면의 ‘네 루트 이오·알렉산드라 확보’ 묶음은 세오도라12장 보관용 자격 준비로 옮기고, 다른 루트에도 각각 종료 전 준비를 둔다. 실제 행동이 아닌 이유 설명은 메모에 둔다.

레다1장에 있던2장 상자·3장 올림피아 육성, 카이1장에 있던2장 여관 복귀 전 확인도 해당 장으로 옮겼다. 디트리히 시작 소지품 점검은 첫 전투보다 앞에 둔다.

## 완료와 다음 단계

- 세오도라·레다: 마지막 주간 봉사·동료 명단·보관용 자격·장비 점검을1부 완료보다 앞에 둔다. 완료 뒤에 위업록 보상을 받고 다음 루트 시작 전 준비로 간다.
- 디트리히: 동료 명단·보관용 병종·장비 확인 뒤11/27 최종전, 그 뒤 새1부 완료 자료로2부를 시작한다. 같은 루트 첫5,000파편을 다시 받는 것으로 계산하지 않는다.
- 카이:1부 종료 전 명단·봉사·보관 준비가2부 시작 뒤로 밀려 있던 순서를 고쳤다.1부 완료 → 보상 →2부 첫 보관 스킵 → 재시작·재장착 → 직접 육성으로 나눈다.
- 첫2부 보존 절차 읽기와 레다 물품 점검은 레다2부6장 첫 완료 직전이다. 완료 뒤 보상 확인·탑승 자료 재등록으로 이어진다. 디트리히·세오도라·카이도 각 첫 스킵 바로 앞에서 그 루트의 물품을 확인한다.
- 디트리히2부의 ‘종료 뒤 기록 확인’은 직접 육성 안내 뒤로 옮긴다. 카이7장 마차 의뢰도6장 묶음 뒤의7장 점검 안에 둔다.3부는 진입 전 완료 확인 → 진입 후 마구간 → 영입·융합 → 구간별 행동의 기존 순서를 유지한다.

## 근거와 보존 범위

- 영입: 로컬 도감의 `data/recruitment-build-audit.json`, 현재 루트 계획의 `data/roster-plan.json`.
- 동선·시점: `data/playbook.json`, 각 루트 원문, 기존 `data/chapter-gold.json`의 실제 교섭 예정 장.
- 첫 반입: [물품·탈것 보존 검토](inventory-mount-review.md), [현재 이월 상태](carry-hard-review.md).
- 체크: 기존ID와 명시 체크값을 보존한다. 옮긴 행동은 원래 묶음의 완료 상속 관계도 유지한다. 새 행동은 기존 묶음의 완료만으로 끝났다고 표시하지 않는다.

검증은 Windows Python·브라우저에서 문서 순서·선행 관계·화면·JSON 보존을 확인하는 범위다. 게임의 새 영입 날짜, 달력의 모든 활동을 한 턴씩 실행한 최단 동선, 전투·성장 결과를 재현한 것은 아니다. 상세는 `checklist-order-validation.json`에 기록한다.
