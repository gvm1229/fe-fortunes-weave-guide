# 영입 물품·지원 집중·체크 조작

2026-11-03 작업 시작, 11-04 완료 · 현재 프로젝트만.

## 영입 물품 위치

현재 개인화의 영입 물품4종(반짝반짝어·시인의 비문/비석 사본·성수·철의 활)을31곳의 실제 버튼으로 바꿨다. 물품이 필요한 인물 표9판을 모두 포함한다. 일반 선호 선물·교섭금·토벌 의뢰는 수집 물품으로 바꾸지 않았다.

중앙 모달에는 인물·수량·탐색/구입 구분, 위치 이름, 실제 위치 그림, 준비 순서와 지도 열기 버튼이 있다. 누조의 철의 활은 디트리히2개와 다른 세 루트3개를 구별한다. 지도 버튼은 누른 인물/행동의 루트에 맞는 주소를 고른다.

브라우저에서 Game8 지도에 들어가 루트·검색어·결과·실제 핀을 직접 조작했다. 브론테스호의 네 루트 채집 목록에 Paradise Fish를 확인했고, 제도 네 루트 무기 목록에서 Iron Bow를 확인했다. 각 핀의 공유 버튼을 눌러9개의 주소를 복사했다. 새 탭의 주소가 실제 물품 모달 지도 버튼의 주소와 일치하는 것도 확인했다. 그 추가 탭의 본문 프레임 제어는 시간 초과여서 자동 핀 표시까지 새 탭에서 확인했다고 세지 않는다.

성수 구입은 로컬 인물 도감 기준이며 Game8 지도는 도시 위치 그림으로 쓴다. Atla Peak 팝업은 일반 광석 목록을 보여 준다. 사본 입수 안내와 기존 이동 그림은 로컬 도감·Game8 일문 시로코 공략을 따른다. 사진과 세부 출처는 `assets/recruitment/SOURCES.md`다.

## 지원 집중

실제 이름이 있는 지원 준비25묶음에43개 초상화 연결을 표시한다. 별도 대상이 없는 초기 장·이미 준비한 교섭만 확인하는 장의 반복 문구는 생략한다. 날짜를 놓치지 말라는 중요한 문구3개는 주의사항으로 옮겼다. 대상별 긍정 계획과 공통 준비의 일반 규칙을 구별한다.

초상화는 지원 대상40×47, 기존 막타22×26을 유지한다. 빈 지원 집중 항목은 출력하지 않으며 같은 장의 지원 집중 제목은 한 번만 나온다. 세오도라 리네의 비숍 운용 문구도 창 전열이 아닌 원거리 회복으로 일치시켰다.

## 체크박스 자체만 조작

행동 문장을 체크박스와 연결한 `label`에서 일반 `div`로 바꿨다. 체크박스는 문장 전체를 `aria-label`로 읽을 수 있지만 문장·여백·소재 버튼을 클릭해도 체크되지 않는다. 체크박스 크기는26px다.

완료 행은 회색23% 반투명 레이어를 표시한다. `pointer-events:none`으로 소재 버튼을 가로막지 않고, 체크박스와 초점은 레이어 위에 남긴다. 해제하면 레이어도 없어진다. 설정용 ‘완료 숨기기’는 진행 체크와 별개로 기존 동작을 유지한다.

## 검증 범위

- Windows Chrome 1440×1000: 네 물품 모달, 지도 주소의 루트 일치, 그림 로딩, 문장/소재 버튼 클릭과 체크 상태 분리를 확인했다.
- Windows Chrome 390×844: 본문19px, 중앙 위치 오차0px, 가로 넘침 없음, 지도 버튼과 그림 로딩을 확인했다. 모바일 모달의 활성화는 키보드 Enter로도 시험했다.
- 물품 모달 전후 체크6508px·공통 준비2980.666748046875px·인물404px, 검색어·루트·주소가 같았다.
- 실제 진행 정본 대신 임시 폴더의 JSON을 쓰는 별도 localhost 검증 서버에서 체크/해제했다. 문장 클릭은 변화 없음, 체크 시 `data-done=true`와 `rgba(105,111,117,.23)`, 완료 후 소재 버튼 사용 가능, 해제 시 레이어 없음이 확인됐다. 작업 도중 외부에서 갱신된 실제 진행 기록은 되돌리지 않았다.
- 체크ID540개(행동447·이전 묶음93), 기존 문서/새 문서22개의 문구·표 값2,998개와 출처를 보존했다. 실제 전투·영입·구입·게임 진행을 실행하거나 체크에서 추정하지 않았다.
