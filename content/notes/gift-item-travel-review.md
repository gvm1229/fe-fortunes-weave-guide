# 선물·아이템 이름·마차 안내 검토

2026-11-04 · 현재 프로젝트. 팀 비교안은 승인 전 상태로 유지한다. 게임 진행·영입·구매를 실행한 기록은 아니다.

## 선물

- [Game8 인물별 선호 선물](https://game8.co/games/Fire-Emblem-Fortunes-Weave/archives/623690)을 Windows Chrome에서 직접 열어 표를 읽었다. 일반 웹 도구는402, Jina 공개 읽기는403이어서 브라우저를 사용했다.
- 로컬 표시 자료50명의 첫 두 선호품을 영문 이름과 대조했다. 모두 원문의 Loved 또는 Really Liked에 포함됐다. 정확한 후보는 gift-candidates-verified.json에 있다.
- 현재 루트별 영입 지원2 이상인 직접 영입에만 선물 후보 행을 표시한다. 자동 합류·지원1은 행 자체를 생략한다. 주간 공통 준비의 선물 안내도 같은 조건을 따른다. 2·3부에서는 영입 선물 행을 숨긴다.
- [전체 선물 도감](https://game8.co/games/Fire-Emblem-Fortunes-Weave/archives/621535)의 공용 선물 종류 그림2종을 내려받았다. 개별 아이템의 고유 외형이 아니라 선물임을 구별하는 실제 아이콘이다.18개 표시 이름의 주소·그림 연결은 assets/gifts/manifest.json에 있다.
- 선물을 몇 개 주면 지원3이 된다는 미확인 개수는 추가하지 않았다.

## 아이템 이름

- 원인: 문장 속 ‘검·활’도 모두 기능으로 인식했고, 이미 무기 이름으로 표시한 구역에도 다시 기능 아이콘을 넣었다.
- 해결: 무기 전체 이름을 먼저 읽고, 아이템 이름 구역은 다시 꾸미지 않는다. 등급 없는 일반 문장의 ‘검·활’은 자동으로 꾸미지 않는다. ‘검 C·궁술 B’와 명시적인 사용 가능 무기 표시는 아이콘을 유지한다.
- 체크·무기 표·입수처 참고 HTML을 같은 표시기로 다시 만든다.

## 카이7장 마차

- [의뢰 원문](https://game8.co/games/Fire-Emblem-Fortunes-Weave/archives/625377): 다그시온 투기장 근처 마부 수주 → 메가이라 시장 Custom Axle1개500G → 같은 마부 보고. 카이7장, 기한11/27. 보상5,000G·명성 점수130 및 마차 이용.
- 차축 구매500G를 카이7장 기본 준비액에 추가했다. 기본13,050→13,550G. 이미 마차 이용 가능·부품 보유면500G를 제외한다. 보상은 받기 전에 지출 가능 현금으로 세지 않았다.
- 기존 모호한 행동2개의 ID는 유지하여7장 마차 구역으로 옮기고, 구매 행동1개를 사이에 추가했다. 수주·구매·보고는 모두 본문에 남긴다. 밑줄 의뢰명은 위치·그림·이동 설명이 있는 중앙 모달을 연다.
- 이미 마차를 쓸 수 있으면 의뢰·구매·보고 반복을 생략한다. 사용자가 모든 역과 공통 의뢰를 완료했다고 보고한 상태와 모순되는 재수집 강요를 피한다.
- ‘차축 부품’은 Custom Axle의 설명 이름이다. 한국어판 정확한 아이템 표기는 확인하지 못했다. 원문 표기를 함께 남긴다.

## 확인 범위

로컬 Windows의 문서 생성·표시 규칙과 브라우저 화면을 확인한다. 실제 게임의 구매 화면·의뢰 완료·지원 상승 결과를 재현한 검증은 아니다. 체크 JSON과 승인 전 팀 편성 정본은 변경하지 않는다.

## 화면·문서 검사 결과

참고 HTML131개·문구/표7,735개 보존. 현재 체크1,068개 고유, 실제 체크JSON과 팀 정본 미변경. Windows Chrome에서 리네 선물 그림, 소피아 지원1의 후보 행 없음, 2·3부 행 숨김, 카이 설명 중앙 모달과 닫기 뒤 세 스크롤 위치 보존을 확인했다.

좁은 화면은 크기 변경 도구가 실제 창에 반영되지 않아 이번에 실검증하지 못했다. 기계 디자인 검사는 기존 작은 병종 태그 여백·글자 위계·반복 금액·그림자 경고를 냈다. 이번 범위 밖의 전체 재설계는 하지 않았다.
