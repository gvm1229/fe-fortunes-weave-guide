# 개인화 React 정본 정리 · 2026-11-12

## HTML이 남아 있던 이유

이전 전환은 독립 개인화 HTML 두 개를 만든 뒤 React가 그 내용을 가져오는 구조였다. 화면은 React였지만 내용 생성 경로에 옛 화면이 남아 있었다.

이제 화면 코드는 `personalized-app/src`, 내용은 `data/`의 JSON을 정본으로 쓴다. JSON에서 내용 조각을 만들어 React와 직접 묶는다. `personalized-app/index.html`은 React 진입 파일이고 `bundle.html`은 브라우저 실행용 결과다. 둘은 별도로 관리하는 공략 화면이 아니다.

- 삭제: 루트의 `personalized.html`, `personalized-team.html`, 두 파일의 독립 JavaScript, `checklist-state.js`.
- 제거: 옛 화면 생성 경로와 쓰지 않는 `build_personalized_team.py`, `render_roster.py`, `illustrate_guide.py`. 공통 내용 서식 함수는 유지한다.
- 현재 주소: `/guide`, `/team`. 예전 `.html` 주소도 같은 React 실행 파일로 연결한다.
- 체크 허용 ID는 HTML에서 찾지 않고 `data/playbook.json`에서 읽는다.

## 요청 내용 확인

- 세오도라 → 레다 → 디트리히 재육성 → 카이의 1부 네 번, 같은 순서의 2부 네 번, 공통 3부다.
- 레다 1부 보상 바로 뒤 병과 경험치 +1에서 +2로 올린다. 추가 2,000파편이며 실제 보유·해금을 확인한다. 이미 산 단계는 다시 사지 않는다.
- 던전 반복은 1·3부에서 다음 시험 시기가 가까운데 필수 기능이 부족할 때 진행한다. 2부 반복 과제는 제외한다.
- 3부에서 필요한 마스터 스킬은 해당 병과로 전직해 던전에서 얻고 장착한다. 신장직은 자격 반납으로 전용 아이템을 돌려받아 다음 인물에게 넘긴다. 마지막에는 최종 담당자에게 배정한다.
- 더 블레이드는 속도 +10, 디 이터널은 힘 +10, 디 아바타르는 마력 +10을 안내한다. 던전은 사용자가 선택한 획득 방법이며, 게임 전체에서 마스터 스킬을 얻는 유일한 방법이라는 뜻은 아니다. [신장직 마스터와 반납 근거](https://annasnotebook.net/en/mechanics/strategy/salvation-five-teams/)

기존 완료 체크·구매 확인·반입 기록·최종25인 편성은 작업 전 파일과 대조한다. 이전 던전 완료 6건은 이력으로 보존하고 새 조건을 완료로 추정하지 않는다.

## 멈춤 방지

Python 120초, TypeScript 60초, React 생성 120초, 파일 합치기 60초 제한을 둔다. Windows에서 시간 초과한 도구의 자식 프로세스도 종료한다. 매 빌드의 패키지 재설치를 없애고 설치된 도구만 쓴다. 새 결과가 완성될 때만 실행 파일을 바꾸며 원본 진입 파일은 건드리지 않는다.

이번 재검증에서 패키지 파일 조회까지 일시적으로 멈췄다가 회복된 것은 관찰했지만 원인은 확인되지 않았다. 과거 8시간 중단의 Windows 비정상 종료 기록과 이번 파일 조회 지연이 같은 원인이라고 단정하지 않는다. 시간 제한은 응답하는 Windows에서 실행 대기를 제한하며 운영체제 자체의 멈춤을 예방한다는 보장은 아니다.

## 검증 범위

Windows의 Python·Node·Chrome에서 내용 생성, 형식 검사, React 묶기, 단계·체크 ID·글꼴 검사를 실제 실행한다. 임시 체크 저장소에서 저장·새로고침·명시적 해제, 네 주소의 같은 실행 파일, 25인·백마술21종·참고 모달을 확인한다. 실제 게임 실행·후퇴 경험치 수치·신장직 반납은 이번에 실측하지 않았다.

형식 검사를 일부러 멈춘 별도 시험에서 60.4초 뒤 자식까지 종료됐고, 이전 실행 파일과 원본 진입 파일이 유지됐다. 과거 독립 HTML·옛 편성 수치를 전제로 하는 검사들은 현재 통과 근거로 쓰지 않는다. 현행 검사 목록은 [React 앱 안내](../personalized-app/README.md)에 있다.
