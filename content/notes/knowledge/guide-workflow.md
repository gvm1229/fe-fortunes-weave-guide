# 공략 작성 방식

범위: 현재 프로젝트만. 출처는 [명시 발화 출처](sources.md)에 있다. 게임 상태와 선호를 섞지 않는다.

### W01 짧고 쉬운 한국어로 설명한다

먼저 핵심을 말하고 필요한 이유·조건을 붙인다. 고유명사와 시스템을 이미 안다고 가정하지 않는다. 한두 문장으로 끝나는 설명은 행동 옆에 쓰고, 더 긴 설명은 이름을 누르면 열리는 참고 모달로 제공한다. [S46](sources.md#s46), [S50](sources.md#s50)

### W02 먼저 프로젝트의 공략 구조를 읽는다

`index.html`부터 읽어 개인 공략·진행 기록임을 파악한다. 기존 왼쪽 메뉴·오른쪽 본문 형식을 따르고 코딩 제품을 새로 만드는 작업으로 확대하지 않는다. [S38](sources.md#s38), [S46](sources.md#s46)

### W03 필요한 현재 상태를 적극적으로 묻는다

공략을 읽고 판단에 필요한 미확인 상태를 구체적으로 질문한다. 사용자는 자세한 질문에 답할 의사가 있다. 질문에 답하는 부담을 반복 육성 부담과 같은 것으로 취급하지 않는다. [S45](sources.md#s45)

### W04 로컬 공략과 실제 플레이 근거를 함께 대조한다

한국어·영어 실제 경험담을 찾아 판단에 쓴다. 로컬 공략, Game8의 관련 하위 문서, 필요한 다른 출처도 비교한다. 같은 글의 복사본은 독립 근거로 늘리지 않는다. [S03](sources.md#s03), [S14](sources.md#s14), [S46](sources.md#s46)

### W05 다른 작품 자료는 비교 근거로 쓴다

풍화설월의 경험치 규칙도 비교에 사용할 수 있다. 만자천홍에서 직접 확인한 사실과 구분하며, 난이도별 클리어 직후 레벨을 비교하라는 요청을 경험치 배율이 확정됐다는 뜻으로 바꾸지 않는다. [S39](sources.md#s39), [S51](sources.md#s51)

### W06 팀 변경은 제안과 적용을 분리한다

현재 편성과 바뀔 편성을 먼저 비교해 보여 준다. 사용자가 구성을 보고 승인하기 전에는 실제 공략·편성 데이터를 바꾸지 않는다. 여성 우선순위·정원·3부 인원·교체 대상을 함께 설명한다. [S01](sources.md#s01), [S02](sources.md#s02), [S03](sources.md#s03)

### W07 진행 보고는 전체와 루트 기록에 함께 남긴다

사용자가 새 진행을 알려 주면 해당 루트의 `progress.md`와 전체 현황을 함께 갱신한다. 제안이나 체크 상태를 실제 플레이 완료로 바꾸지 않는다. 현재 장·능력치·장비는 선호 지식이 아니라 진행 기록이다. [S46](sources.md#s46), [S14](sources.md#s14)

### W08 실제 지출과 완료를 추측하지 않는다

이미 구매·수령했다고 사용자가 밝힌 것, 아직 구매할 예정인 것을 구별한다. 수치가 달라 보이면 묻거나 근거를 확인한다. 소지품과 장착품, 속도와 공격 속도도 섞지 않는다. [S41](sources.md#s41), [S42](sources.md#s42), [S43](sources.md#s43), [S44](sources.md#s44)

### W09 날짜가 있는 행동은 본문 체크에 둔다

특정 날짜·장소·대화·전투 중 회수처럼 놓치면 곤란한 행동은 루트의 해당 시점에 바로 표시한다. **선택 시합·관전·행사·생일·선택 장면도 확인된 일정은 모두 본문 실행 체크로 둔다.** 선택 콘텐츠나 작은 보상이라는 이유로 목록에서 빼거나 메모·‘별도 일정’ 안내만 남기지 않는다. 귀환·대화/관전·전투를 필요한 행동으로 나누고 주간 봉사와 실제 날짜순으로 배치한다. 같은 날짜라도 루트별 자유행동·참가 가능 여부를 개별 확인하고 기존 완료값은 보존한다. 자료에 없는 날짜는 만들지 않으며 실제 달력 확인도 장 시작 체크에 둔다. 지원 따라하기·구매 비교 같은 참고 자료는 모달로 둔다. [S13](sources.md#s13), [S38](sources.md#s38), [선택 일정 누락 정정](sources.md#optional-schedules-checks-20261105), [나머지 세 루트 적용 요청](sources.md#other-routes-schedules-20261105)

### W10 동선과 준비를 함께 안내한다

이동할 곳, 필요한 물품, 지원을 올릴 인물과 시기를 장별 순서에 넣어 왕복과 턴 낭비를 줄인다. 장소 이름만 나열하지 않는다. 실제 최단 턴을 측정하지 않았다면 최단 경로로 확정하지 않는다. [S33](sources.md#s33), [S36](sources.md#s36)

### W11 영입 물품의 수주 조건을 먼저 확인한다

모든 물품을 미리 모을 수 있다고 가정하지 않는다. 의뢰가 먼저 필요한 경우 조건 충족 → 본인에게 수주 → 재료 수집 → 보고를 루트 행동·동선·소재 모달에 함께 반영한다. [S06](sources.md#s06), [S07](sources.md#s07)

### W12 사야 할 물건은 만나는 시점에 판단할 수 있게 쓴다

좋은 무기를 알아보지 못해 나중에 후회하는 일을 줄인다. 로컬 공략과 입수·구매 자료를 대조하여 루트별 필요한 수량과 사야 할 이유를 표시한다. 질문만으로 선더 소드 3~4개를 무조건 필수로 확정하지 않는다. [S16](sources.md#s16), [S40](sources.md#s40)

### W13 장 시작에 준비할 골드와 용도를 표시한다

그 장에서 지출 전에 확보할 돈과 ‘단테 영입용’ 같은 이유를 본문에서 바로 볼 수 있게 쓴다. 실제 지출 뒤에도 같은 돈을 다시 벌라는 식으로 중복 과제를 만들지 않는다. [S11](sources.md#s11)

### W14 장별로 경험치를 줄 대상을 알려 준다

누가 적을 마무리하면 좋은지 행동 옆에 표시한다. 현재 부·루트·정원에 맞춰 선택과 집중을 돕고 모든 동료를 똑같이 키우게 만들지 않는다. [S17](sources.md#s17), [S29](sources.md#s29), [S33](sources.md#s33)

### W15 막연한 기준은 근거와 수치로 풀어 쓴다

‘명성이 레벨을 못 따라오면 낮춘다’ 같은 말은 무엇을 언제 조절하는지 설명한다. 자료에 없는 정확한 대응 수치나 해금 시점을 만들어 채우지 않는다. 사용자의 질문 속 가설은 게임의 확정 규칙이 아니다. [S06](sources.md#s06), [S28](sources.md#s28)

### W16 작업 과정 문구를 공략 화면에 넣지 않는다

‘새 기준을 반영했다’, ‘접지 않고 모두 표시한다’처럼 사용자 요구를 되풀이하는 문구를 빼고 실제 행동·게임 조건·필요한 설명을 쓴다. [S35](sources.md#s35)

### 전직 시점과 경험치 조절의 목적을 함께 적는다

명성별 권장 레벨과 경험치 보너스 ON/OFF를 안내할 때는 좋은 성장 병과로 제때 전직해 그 병과에서 레벨업하려는 이유를 짧게 설명한다. 기본 경험치와 추가 보너스, 실제 게임 설정 변경과 공략 설명을 구별한다. [명시 요청](sources.md#growth-xp-purpose-20261104)

### 경험치 조절은 실행 체크에도 둔다

권장 레벨 직전의 경험치 보너스 해제는 설명에만 두지 말고 사용자가 확인할 실행 체크로 표시한다. 목표 성장 병과 준비 후원래값으로 켜는 확인도 함께 안내한다. 상위 단계의 언급을 묻는 질문을 구매 실행 승인으로 바꾸지 않는다. [명시 요청](sources.md#xp-toggle-checklist-20261104)


## 영입 명단·지원 준비의 일치

인물 명단에 없는 별도 영입 행동을 활성 체크에 넣지 않는다. 지원2 이상 계획 영입자는 대기열에 표시하고, 실제 개방 시점·활동 명단 등장·현재 로드 지원·본대 우선순위에 따라 준비한다. 세오도라는5장 군비증강 안내 뒤 선물·스카우트가 열린 다음부터 실행한다. 이전의 일괄 ‘첫 다그시온부터’ 기준 중 세오도라4장 적용을 대체한다. [개방 시점 정정](sources.md#theodora-scout-opening-20261105). 최종25명의 보완판도 빈 출격 칸·추가 비용·다른 성장 축의 이득이 있을 때만 선택한다. 출처:2026-11-04 울턴드 영입 불일치 후속 요청.


### 실제 구매 목록을 다음 루트 준비에 이어 쓴다

사용자가 구매 완료 목록을 확인하고 체크 완료를 요청하면 해당 구매를 저장한다. 이미 가진 단계는 뒤 루트 구매 행동에서 빼고, 상위 단계의 추가 비용과 새 첫 완료 보상 수령을 구분한다. 현재 메뉴 상한을 게임 전체의 최종 상한으로 바꾸지 않는다. [명시 요청](sources.md#boon-purchase-carry-20261104)


### 행동은 실제로 실행할 수 있는 시점에 배치한다

축복 구매는 각 루트의 새1장을 선택하기 전 맨 위에 둔다. 영입금은 해당 동료의 교섭이 임박했을 때, 영입 후 병종 판단은 실제 영입 다음에, 보존·최종 명단 확인은 완료 전에 둔다. 다음 루트1장을 먼저 선택시킨 뒤 축복 준비를 시키지 않는다. [명시 요청](sources.md#checklist-action-order-20261104)

등장·기능 개방과 실제 요구 명성 충족을 구분한다. 사용자가 확인한 현재 명성을 기준으로 지원 선행 준비와 수주·원정·시험·영입을 따로 배치하며, 다음 장의 예상 명성을 실제 도달값으로 기록하지 않는다. [명시 정정](sources.md#renown-gated-order-20261105).

### W17 장비 회수·병과 선택의 이유를 적는다

동료의 장비를 회수하거나 육성을 중단하라고 안내할 때는 왜 그 행동이 필요한지 짧게 적는다. 이유가 이야기의 반전을 드러내면 빨간 ‘스포일러’ 버튼 안에서 설명하고, 실행할 행동은 본문 체크에 남긴다. 특정 루트만이 아니라 모든 루트에 같은 기준을 적용한다. [명시 요청 R16](session-review-20261104.md#r16)

추천 영입·육성·자료를 제외하거나 없애는 변경도 대상·목적·얻는 이득·잃는 역할·복구 가능성을 검토하고 완료 후 이유를 명확히 설명 · 이유 없는 파괴적 변경 금지 · 같은 병과의 성장 중복과 현재 부대의 회복·전열 가치를 분리 · [2026-11-06 재검토 요청](sources.md#readiness-healing-20261106)

### 출격 역할과 미래 육성 준비를 분리

본대·보완은 현재 부의 출격,기준판·능력 보완·실전 회복·보존은 자료의 용도 · 최종25명과2부 본대 예약자는1부에서Lv20·중급 자격과 상급의 필수 기능 준비 · 늦은 상급 합류·탈것 보존판의 기존 자격은 소급하지 않음 · 영입 지원 시작·권장 합류 장·투자 시작/종료를 인물별 표시 · 루트 고유 인물은2부까지 실전으로 쓰되3부 예비 전환 뒤에는 필요할 때만 추가 투자 · 주간 훈련 종류마다2인 조·미영입/목표 달성 시 다음 후보 제시 · [같은 요청](sources.md#readiness-healing-20261106)

병과 경로에는 성장률·이동력·마스터 보상 등 선택 목적을 적고, 다음 병과의 필수 선행 자격·마스터인지 구별한다. 생략 가능한 경유는 선택사항으로 표시하고, 성장 병과 유지·자격만 취득·전투별 교체도 구분한다. [명시 요청](sources.md#2026-11-05-병과-선택-이유와-선행-조건)

성장률·이동력·마스터 보상은 짧은 비교표로 모으고, 반복되는 공통 규칙은 한 번만 표시한다. 병과별로는 그 인물이 고르는 이유·생략 가능 여부·꼭 필요한 조건과 예외를 짧게 남긴다. 이전의 병과마다 긴 항목을 반복하는 표시를 대체한다. [압축 요청](sources.md#compact-people-20261106)

### W18 상위 축복 구매는 실제 필요성을 먼저 따진다

더 높은 경험치 축복을 살 수 있더라도 실제 플레이 사례와 성장에 필요한 이득을 확인한 뒤, 어떤 축복을 언제 살지 공략 수정안을 검토한다. 사용자가 ‘필요하면 구매 가능’이라고 말한 것을 즉시 구매·구매 완료로 바꾸지 않는다. 현재 해금과 보유 단계·예산에 맞춰 판단한다. [명시 요청 R02](session-review-20261104.md#r02)

### 직접 보고한 완료와 진행 중을 구별해 체크한다

사용자가 실제 진행을 알리고 체크 반영을 요청하면 확인된 완료만 같은 응답에서 저장한다. 지원을 올리는 중이라는 보고를 목표 지원 달성이나 영입 완료로 바꾸지 않는다. 이미 저장된 완료는 유지하고 모르는 수치는 채우지 않는다. 현재 장·명단은 전체/루트 진행 기록에 둔다. [명시 요청](sources.md#theodora-check-report-20261105).

### 선준비는 사용할 장·목적·한국어 이름을 붙인다
