# 화면 사용 방식

범위: 현재 프로젝트의 개인화 공략. [명시 발화 출처](sources.md)를 따른다. 이 문서는 선호 정리이며 이번 작업에서 화면을 다시 수정한 기록이 아니다.

## 행동과 배치

### U25 모든 공략 화면에 Pretendard를 사용한다

앞으로 만드는 비교 페이지와 생성 HTML에도 프로젝트의 로컬 `fonts.css`를 연결한다. 파일을 추가하거나 생성 도구를 수정한 뒤 `python tools/check_fonts.py`로 누락을 확인한다. 출처: 현재 프로젝트 대화에서 사용자가 명시한 요청(2026-11-04).

### U01 한 행동씩 자주 체크한다

한 묶음을 끝내는 데 오래 걸리지 않도록 바로 실행하고 확인할 작은 행동으로 나눈다. 블록은 긴 설명 문단보다 실행 순서가 있는 목록으로 쓴다. 실수를 막는 조건은 줄이지 않는다. [S30](sources.md#s30), [S34](sources.md#s34)

### U02 행동 목록과 관련 정보를 함께 본다

행동은 왼쪽 한 열, 현재 루트 인물·공통 준비는 오른쪽에서 볼 수 있게 한다. 개인화 페이지의 가로 여백을 줄인다. 공통 정보는 다른 루트로 바꾸더라도 다시 찾아 열게 만들지 않는다. [S30](sources.md#s30)

### U03 공통 준비와 인물은 한 공간의 가로 탭으로 둔다

두 정보 상자를 위아래로 쌓아 각각의 읽을 공간을 줄이지 않는다. 위쪽의 ‘공통 준비’·‘인물’ 버튼으로 전환하고 현재 탭을 분명하게 강조한다. [S08](sources.md#s08)

### U04 페이지 바깥은 움직이지 않는다

화면에 페이지를 맞추고 할 일·준비·인물·메뉴는 각각 안에서 스크롤한다. 한 영역을 움직일 때 다른 영역은 그대로 둔다. 머리글은 고정하고 스크롤에 따른 숨김·전환 애니메이션을 없앤다. [S28](sources.md#s28), [S33](sources.md#s33)

‘다음 할 일’은 할 일 상자의 스크롤만 조정한다. 페이지 바깥·머리글·오른쪽·메뉴를 움직이거나, 탭·루트·필터·체크 등 다른 상태를 바꾸지 않는다. [동작 범위 정정](sources.md#next-action-scroll-20261106)

### U05 영역마다 바로 이동하고 숨길 수 있다

각 스크롤 머리에 ‘맨 위로·맨 아래로’를 둔다. 각 영역의 눈 아이콘과 화면 오른쪽 위 버튼으로 표시를 바꿀 수 있게 하여 왼쪽 위까지 커서를 옮기는 일을 줄인다. 옛 전체 ‘맨 위’ 버튼 요청은 영역별 이동으로 대체됐다. [S09](sources.md#s09), [S28](sources.md#s28), [S34](sources.md#s34)

### U06 필수 준비는 표시하고 선물 후보는 접는다

실행에 필요한 준비와 조건을 접힌 구역 안에 숨기지 않는다. 특정 시점의 필수 행동은 본문 체크에 유지한다. 스포일러와 인물표의 선물 후보는 예외 · 선물 후보는 기본 접힘,클릭하면 펼치고 다시 클릭하면 접기. 이전 접기 금지 중 이 부분은 최신 요청으로 대체. [S13](sources.md#s13), [S33](sources.md#s33), [최신 선물 표시](sources.md#gift-disclosure-20261106)

### U07 본문은 큰 글씨와 짧은 요점을 쓴다

가독성을 먼저 챙긴다. 간결하게 쓰되 생략하면 실수할 조건은 남긴다. 인물 설명은 목표·운용·시험·준비·선물·영입을 항목별 표로 구별한다. [S28](sources.md#s28), [S35](sources.md#s35)

인물표는1·2·3부 전환 뒤에도 보이는 셀에 빈칸을 남기지 않음 · 원래 조건·실행 순서를 표시하고,해당 없음·미확인은 이유를 명시 · 모르는 게임 값을 추정해 채우지 않음. [같은 최신 요청](sources.md#gift-disclosure-20261106)

## 체크와 저장

### U08 체크박스만 진행을 바꾼다

문장이나 소재 버튼을 눌렀다는 이유로 완료가 바뀌면 안 된다. 체크박스 자체를 누를 때만 바꾸고 완료 행에는 회색 반투명 표시를 덮는다. [S21](sources.md#s21)

### U09 체크는 프로젝트 JSON에 저장한다

확인한 상태는 바로 JSON에 저장되어 새로고침과 같은 컴퓨터의 다른 브라우저에서도 이어져야 한다. 브라우저별 저장소만으로 진행 정본을 만들지 않는다. [S32](sources.md#s32)

## 모달과 문서

### U10 참고는 화면 가운데에서 읽는다

시험·지원 따라하기·근거·구매 비교는 화면 정중앙의 모달로 연다. 읽던 인물 영역의 맨 아래로 보내거나 다른 페이지로 이동시키지 않는다. 닫으면 기존 체크·준비·인물의 스크롤 위치를 유지한다. [S23](sources.md#s23), [S25](sources.md#s25), [S26](sources.md#s26), [S28](sources.md#s28)

### U11 누른 루트의 정보부터 보여 준다

입수처뿐 아니라 다른 모달도 현재 버튼의 루트에 맞는 내용만 기본 표시한다. 네 루트 정보를 한꺼번에 섞어 혼동시키지 않는다. [S10](sources.md#s10)

### U12 Markdown을 브라우저 링크로 직접 열지 않는다

편집 정본과 읽는 화면을 구별한다. 한글이 깨진 원문 파일 대신 읽을 수 있는 문서 화면을 연결하고 모달에도 같은 가독성을 적용한다. [S22](sources.md#s22), [S26](sources.md#s26)

### U13 긴 용어 설명은 이름을 눌러 연다

한두 문장의 짧은 설명은 체크 옆에 둔다. 더 긴 설명은 고유명사를 밑줄 버튼으로 만들어 모달을 연다. 조건이나 행동 자체를 모달로 옮기지는 않는다. [S50](sources.md#s50)

## 인물과 시각 표시

### U14 얼굴·역할·영입 조건을 크게 구별한다

인물 정보는 역할 → 큰 초상화 → 이름 → 하트 지원 조건 → 반짝 명성 조건 순으로 각 줄에 둔다. 본대·보완·선택 여부를 알아보기 쉽게 표시한다. [S30](sources.md#s30)

### U15 인물은 역할과 영입 시기로 정렬한다

본대·보완·선택을 먼저 나눈 뒤 시작 동료·자동 합류·스카우트 명성 순서로 정렬한다. 검색하면 일치하는 인물만 보여 준다. [S17](sources.md#s17), [S28](sources.md#s28)

전체 비교 모드에서만 인물의 본대·보완 표시 바로 위에 진영장의 작은 초상화와 루트 이름을 붙인다. 일반 루트 보기에서는 이 표시와 그 자리를 모두 숨긴다. [비교 표시 요청](sources.md#compact-people-20261106)

### U16 실제 게임 그림과 지도 버튼을 쓴다

장소·메뉴·소재 안내에 해당 그림을 함께 둔다. 지도는 지도 아이콘이 있는 버튼으로 연다. 병종에는 실제 아이콘과 초급·중급·상급 등 등급을 함께 표시한다. [S20](sources.md#s20), [S36](sources.md#s36)

### U17 수치의 의미에 같은 모양을 쓴다

지원 집중·조건·제목은 하트와 같은 지원 배경을, 명성은 반짝과 회색 태그를 쓴다. 신의 가호 수치에도 이름 왼쪽에 신의 실제 초상화를 붙인다. [S12](sources.md#s12), [S30](sources.md#s30), [S37](sources.md#s37)

### U18 필요한 곳에만 초상화를 붙인다

지원 집중 대상에게 얼굴을 붙이고 대상이 없으면 빈 안내를 반복하지 않는다. 막타 배분의 얼굴은 작게 하여 글줄을 밀지 않는다. 주간 식사·선물의 초상화는 해당 인물 정보로 연결한다. [S20](sources.md#s20), [S28](sources.md#s28), [S29](sources.md#s29)

### U19 영입 물품은 별도 위치 안내를 제공한다

필수 재료 이름을 누르면 수집·구입 위치, 해당 위치 그림, 지도 버튼이 있는 모달을 연다. 일반 선호 선물과 필수 재료를 구별한다. [S20](sources.md#s20), [S50](sources.md#s50)

### U20 선물 후보는 필요한 직접 영입에만 표시한다

직접 영입의 요구 지원이2 이상인 인물에게만 선물 후보 행을 제공 · 자동 합류·지원1에는 행 자체를 표시하지 않음 · 후보는 기본 접힘 아코디언에서 정확한 이름·아이콘·기본 가격을 표시하고 반복 클릭으로 열기/닫기 · 후보 자체는 삭제하지 않음. [S50](sources.md#s50), [최신 확인](sources.md#gift-disclosure-20261106)

### U21 아이템 이름을 아이콘으로 쪼개지 않는다

기능 등급·사용 가능 무기 종류를 표시할 때 아이콘을 쓴다. 아이템 이름 안에 ‘검’·‘활’이 있다는 이유로 이름 중간에 기능 아이콘을 넣지 않는다. [S50](sources.md#s50)

### U22 그림 뒤의 문구까지 세로 정렬한다

얼굴과 이름만 맞추지 말고 뒤에 붙는 짧은 용도·수량 문구도 같은 줄에서 세로 중심을 맞춘다. 긴 본문의 자연스러운 줄바꿈은 유지한다. [S12](sources.md#s12)

### U23 개인화 메뉴의 선택 상태를 분명하게 보여 준다

기존 왼쪽 메뉴·오른쪽 본문을 유지하고 개인화 메뉴는 맨 아래 둔다. 미선택의 빨강·노랑과 선택 상태를 구별하여 현재 위치를 바로 알아볼 수 있게 한다. [S35](sources.md#s35), [S38](sources.md#s38)

### U24 주간 활동은 대상과 필요한 때를 적는다

누구와 식사하고 누구에게 선물을 줄지 보여 준다. 지원 반복과 다음 로드 선행 식사는 실제 필요한 때를 밝혀 선택적으로 권한다. 부별 목표는 서로 다르게 제시하되 자료에 없는 병종 해금을 확정하지 않는다. [S28](sources.md#s28)

### 병과 이름의 상세 모달

병과 이름을 누르면 시험 조건·병과 스킬·마스터 보상을 중앙 모달로 연다. 제목은 실제 병과 아이콘과 이름으로 구성하고, 조건에는 기능 아이콘·명성 태그를 사용한다. 닫으면 각 영역의 읽던 스크롤 위치를 유지한다. [명시 요청](sources.md#class-modal-20261104)

### 병과 정보 표시의 일관성

가입 후 목표와 기능 우선순위의 병과 표시에는 같은 사용 무기·특성 아이콘을 쓴다. 병과 모달은 공간에 맞춰 각 아이콘 옆에 짧은 이름을 작은 글자로 함께 표시한다. [명시 요청](sources.md#class-capability-coverage-20261104)

### 기능 우선순위 병과도 같은 세로형으로 표시한다

기능 우선순위의 병과는 가입 후 목표와 같은 컴포넌트를 쓴다. 이름 아래에 등급을 놓는 세로 배치, 병과 그림·글자 크기, 하단 무기·특성 줄을 통일한다. 이전 기능 우선순위의 이름·등급 가로형 표시는 이 요청으로 대체됐다. [명시 요청](sources.md#training-class-vertical-20261104)

### 밝은 화면과 어두운 화면 전환

공략에 어두운 화면을 제공하고, 사용자가 직접 바꿀 수 있는 전환 버튼을 둔다. [명시 요청](sources.md#dark-mode-20261105)

### 두 개인화 화면의 새 구조와 표시 기억 · 2026-11-06

React로 바꾸는 범위는 개인화 공략·개인화 팀 구성 두 화면뿐이다. 기존 공략·팁·도감은 참고 보관 자료로 두고 원래 HTML의 검색·필터를 유지한 채 앱에서 열 수 있게 한다. 이전 React 도입 금지는 이 두 화면에 한해 최신 요청으로 대체됐다. 상단 두 화면 이동과 참고 보관 메뉴가 새 앱의 탐색 기준이며, U23의 맨 아래 빨강·노랑 메뉴는 기존 보관 HTML에 관한 옛 구조다.

메뉴·백마법 등 UI의 열림·닫힘과 선택한 탭·필터·읽던 위치를 새로고침 뒤에도 기억한다. 화면 설정은 브라우저에, 실제 진행 체크는 기존 JSON에 구별해 저장한다. 밝은/어두운 화면 전환은 글자 버튼 대신 해·달 아이콘을 사용한다. 아이콘 버튼에도 동작 이름을 제공한다.

기존 색은 유지하지 않는다. 공식 배너에서 색을 추출해 제안한 뒤 사용자가 선택한 **1번 아이보리+짙은 남보라**를 적용한다. 차분한 읽기와 깔끔한 구조를 우선하고, 핵심 백마술은 금색으로 구분한다. [현재 요청과 색 선택](sources.md#react-personalized-20261106)

어두운 화면에서 경기병처럼 색이 맞지 않는 곳을 발견하면 그 표시 하나만 고치고 끝내지 않는다. 병과·등급·조건·선물 등 관련 표시 전체를 살펴 같은 문제를 함께 고친다. [어두운 화면 전체 검토 요청](sources.md#dark-theme-audit-20261106)

### 루트별 재료는 체크 없는 참고 목록으로도 둔다

선더 소드 교환 같은 재료 준비는 본문 체크와 별개로 ‘공통 준비·인물’과 같은 공간에 루트별 참고 목록을 둔다. 재료·필요 수량·입수처를 단순하게 나열하고 지도 안내를 연결한다. 참고 목록에는 체크를 추가하지 않으며 완료 숨기기와 무관하게 볼 수 있어야 한다. 준비를 이해해 체크한 것을 실제 수집·보유·교환 완료로 추정하지 않는다. [명시 요청](sources.md#route-material-reference-20261105)



## 채움형 표시·짧은 어투 · 2026-11-05

- 버튼·배지·등급은 투명 배경의 테두리형보다 채움형 우선. 배경과 글자를 같은 색 계열의 짙고 밝은 조합으로 구분. 금색은 짙은 금색 배경·밝은 노란 글자 같은 조합
- 굵은 테두리의 정적 표시는 비교안·인물 체험으로 실제 바뀐 캐릭터 카드에만 적용. 일반 조건·등급 배지에는 테두리 사용 금지
- 역할·병과 등급·핵심 조건을 선택적으로 배지화. 모든 설명을 배지로 만들지 않고 강조와 일반 본문을 분리
- 개인화 진행표·팀 구성·연결 참고의 화면 문구는 마침표 없는 두괄식 짧은 어구. 숫자·조건·게임의 정확한 인용·고유명사·진행 체크 의미는 보존

출처:2026-11-05 현재 대화의 채움형 UI·굵은 테두리 예외·단답형 어투 후속 요청

## 공략 읽기 크기와 장 순서 · 2026-11-06
본문과 조건·표의 작은 글씨를 함께 점검하고 초상화는 원본 비율을 보존한다. 장 시작 안내보다 해당 장의 할 일이 먼저 나타나지 않도록 배치한다. 준비 기한을 현재 장으로 잘못 바꾸지 않는다. 출처:2026-11-06 현재 대화의 공략 글자·초상화·장 표시 수정 요청.

## 시간 경과 후 초상화 · 2026-11-07
최종25인에서 시간 경과 후 초상화를 ON/OFF로 전환하고 설정을 기억한다. 개인화 공략3부는 해당 그림을 기본으로 사용한다. 별도 그림이 확인되지 않은 인물은 원래 그림을 유지한다. 출처:2026-11-07 현재 대화의 초상화 수집·전환 버튼·3부 기본 적용 요청.

시간 경과 후 표시도 기존 assets/portraits처럼 얼굴을 가까이 보여 주는 별도 원본을 사용한다. 큰 초상화를 그대로 축소하는 이전 적용은 얼굴 초상화 연결로 대체한다. 출처:2026-11-07 현재 대화의 얼굴 초상화 추가 요청.

얼굴 PNG43개는 post-timeskip 폴더 바로 아래에, 큰 원본43개는 post-timeskip/large에 둔다. 얼굴 그림은 두 개인화 화면에서 정사각형 원본 비율로 표시하고 잘라 넣거나 세로로 늘리지 않는다. 출처:2026-11-07 현재 대화의 폴더 배치·얼굴 비율 정정 요청.

## 체크리스트 제목·인물 정렬 · 2026-11-07
지원 집중 등 메모 제목과 초상화가 겹치지 않게 제목 칸의 내용 너비를 확보한다. 초상화와 이름은 세로 가운데를 맞추고, 막타 배분 같은 짧은 항목 제목은 한 줄로 유지한다. 좁은 화면에서는 제목과 내용을 위아래로 배치한다. 출처:2026-11-07 현재 대화의 체크리스트 시각 오류 첨부·수정 요청.

체크리스트의 모든 루트·장에 같은 정렬 기준을 적용하고 영어 물품·장소 이름이 남으면 한국어 자료와 대조한다. 출처 이름·게임 약어·주소는 이름 번역 대상과 구별한다. 출처:2026-11-07 현재 대화의 전체 루트 시각·영어 이름 전수 점검 요청.

## 새 사이트 화면 규칙 · 2026-11-13
- 스크롤할 때 왼쪽 메뉴뿐 아니라 할 일 머리 줄과 오른쪽 보조 칸(인물·재료)도 고정한다.
- 인물 정보(병종·내용 등)는 행과 열이 분명한 표로 보여 준다.
- 글 덩어리는 가장 나쁜 디자인으로 본다. 나누기·표·아이콘·요약으로 반드시 풀어 쓴다.
- 같은 구역 안의 초상화(인물·신)는 같은 크기로 맞춘다. 구역이 다르면 크기가 달라도 된다.
- 그림은 잘리지 않게 원본 전체를 원래 비율로 보여 준다.
