## React 개인화 화면 정본 정리 · 2026-11-12

개인화의 파일 입력·빌드·서버·검사 경로를 확인한다. React가 공략 데이터에서 직접 내용을 만들도록 바꾸고 중복 개인화 HTML과 별도 화면 생성 경로를 제거한다. 체크 허용 ID는 데이터 정본에서 읽고, 단계 순서·축복·던전 조건·신장직 마스터와 기존 완료 기록을 임시 저장소 및 브라우저에서 검증한다.

재검증 중 TypeScript 패키지 파일 조회가 일시적으로 멈췄다가 회복됐다. 원인은 확인되지 않았다. Python뿐 아니라 형식 검사·묶기 단계에도 시간 제한을 넣고, 매번 패키지를 다시 설치하던 경로를 없앤다. 새 묶음이 성공할 때만 기존 결과를 교체한다.

완료. 독립 개인화 HTML·JavaScript와 이전 생성 경로를 제거하고 JSON → React 빌드로 통합했다. Windows Chrome의 임시 체크 저장소에서 9단계·추가 구매·던전 조건·마스터 이전·25인·모달·저장과 새로고침을 확인했다. 특정 항목으로 이동할 때 페이지 전체가 밀리는 문제도 고쳤다. 실제 체크·구매 확인·반입·편성 파일은 그대로이며, 60초 중단 시험에서 자식 프로세스 종료와 이전 실행 파일 보존을 확인했다. [검토와 한계](react-canonical-review.md), [최종 검사](react-canonical-validation.json)

## 네 루트 전체 순서 제안 · 2026-11-10

1. 세오도라 1부를 끝내고 위업록 보상 5,000개를 받는다. 아우로라·칼라 비용 50% 할인이 열려 있으면 같은 루트 2부로 이어도 된다. 잠겨 있으면 레다 1부를 먼저 한다.
2. 레다 1부를 끝내고 위업록 보상 5,000개를 받는다. 가호 할인과 병과 경험치 +2의 해금을 확인한다. 세오도라 2부를 먼저 직접 완료하고 첫 군단·탈것 보존을 처리한 뒤 레다 2부를 직접 진행한다. 세오도라 2부를 이미 끝냈으면 레다 1·2부를 잇는다.
3. 디트리히는 같은 저장의 방첨탑에서 하드·캐주얼 1부 1장부터 새로 키운다. 이미 채운 디트리히와 동료의 지원 조건은 반복하지 않고, 영입 자체와 현재 명성·교섭 조건은 다시 확인한다. 첫 완료 5,000개는 한 번만 센다. 새 1부를 마친 자료로 디트리히 2부를 직접 진행한다.
4. 카이 1부는 이월 가호·공유 축복으로 진행한다. 전차병을 실제로 쓸 동료의 말과 친밀도를 준비하고, 1부 첫 완료 보상 5,000개를 받는다. 카이 2부는 전원 탈것을 해제해 첫 보관을 등록하고, 재장착해 직접 완료한다.
5. 네 루트의 새 2부 완료 자료와 반입품을 확인한 뒤 3부로 들어간다. 최종전 인원과 탐사·복구 예비 인원을 나눠 재영입한다.

각 루트에서 첫 반입에 앞서 [군단·특별 탈것 보존 절차](theodora-first-war-preservation.md)를 따른다. 이 순서는 앞선 답변에 생략된 디트리히 재육성과 카이를 포함한 검토 제안이다. 네 1부부터 모두 끝낼 경우에는 세오도라→레다→디트리히 재육성→카이의 1부, 같은 순서의 네 2부, 3부다. 카이의 5,000개까지 첫 2부 전에 받지만 가호 할인이 레다 종료 때 열리면 그 할인만을 위해 카이까지 기다릴 이득은 줄어든다.

레다 1부 완료 뒤 직전 추천안의 구매는 병과 경험치 +2(추가 2,000개), 아우로라·칼라 비용 50% 할인(추가 각 300개)이다. 모두 켰을 때 적용되는 축복 13개는 인물 경험치 +10%, 병과 경험치 +2, 검·창·도끼·궁·격투·흑마술·백마술 경험치 각 +1, 무기 가격 10% 할인, 아우로라·칼라 가호 비용 각 50% 할인, 크레르 가호 비용 20% 할인이다. 마지막 보고 잔액 2,605개에 세오도라·레다 첫 완료 보상만 더한 뒤 2,600개를 쓰면 10,005개다. 다른 수입·지출이 없다는 계산 예시다.
