# 개인화 두 화면 React 전환 결과 · 2026-11-06

현재 프로젝트만 작업했다. Hive·전역 지식·외부 게시·게임 저장 파일은 사용하지 않았다.

## 사용할 화면

- 개인화 공략: http://localhost:8766/personalized.html
- 개인화 팀 구성: http://localhost:8766/personalized-team.html
- 마지막 화면: http://localhost:8766/personalized-app/bundle.html

기존 `공략 열기.cmd`로 실행한다. React 소스는 `personalized-app/src/`, 실행 묶음은 `personalized-app/bundle.html`이다. 화면·동작 코드는 React로 작성했고, 내용은 기존 생성 HTML에서 의미와 아이콘을 보존해 가져온다. 다른 공략·도감은 React로 변환하지 않았다. 참고 보관에서는 원본 HTML을 iframe으로 열며 원본 새 탭도 제공한다.

공식 배너에서 추출한 색 중 사용자가 선택한 아이보리·짙은 남보라를 적용했다. 출처와 추출 방법은 `assets/design/SOURCES.md`, 화면 규칙은 `DESIGN.md`에 있다. 해·달 아이콘으로 밝은/어두운 화면을 바꾼다.

메뉴·정보창·백마법·선택 화면·루트·부·검색·역할·육성판·비교안·체험 교체·완료 숨김·선물 펼침·읽던 영역을 같은 브라우저의 화면 설정에 저장한다. 실제 체크는 기존 JSON API로 저장한다. `localhost`와 `127.0.0.1`은 표시 설정이 서로 다르지만 체크 정본은 같다. 중앙 문서 모달의 열림 자체는 새로고침 뒤 복원 대상으로 삼지 않았다.

## 실제 확인한 범위

모든 실행은 Codex의 Windows 호스트에서 했다. 브라우저는 연결된 Chrome이다. 실제 게임 조작·영입·육성 결과를 검증한 작업은 아니다.

- **통과 — 빌드·형식:** TypeScript 검사와 공식 web-artifacts-builder의 초기화·묶기 스크립트 실행. 최종 묶음1,320,887바이트. 이 크기는 코드·문구·CSS이며 기존 그림·글꼴을 포함한 프로젝트 전체 크기가 아니다. 같은 내용을 압축했으며 압축 해제 결과가 입력 JSON과 같음을 확인했다.
- **통과 — 내용·체크 연결:** `python tools/check_react_content.py` 실행. 현재 행동1,516개·이력 포함2,257ID·체크 부모/상속값이 원본과 일치했다. 비교안3개와 체험2개의12조합은 각각 중복 없는25명을 유지했다. 이는 자료 검증이며12조합 모두를 게임에서 실행한 뜻이 아니다. 백마법 효과21개를 포함했다.
- **통과 — 정본 보존:** 작업 전 해시와 체크·백업·전체 진행·최종 편성·부별 목표·행동·공유 상태·구매 계획8개 파일이 같았다. 이 비교는 이 작업이 게임 진행을 갱신하지 않았음을 확인하며 사용자의 실제 게임 화면과 일치하는지는 증명하지 않는다.
- **통과 — 저장:** 기존 로컬 서버 통합 검사9개 실행. 임시 체크 서버에서 실제 클릭→JSON의false 저장, 저장 실패 표시, 재시도와 새로고침 후true 복원을 확인했다. 실제 사용자 체크 JSON은 시험하지 않았다.
- **통과 — 표시 기억:** 브라우저에서 메뉴·백마법 숨김·색상·인물 검색/역할/루트/부와 읽던 영역의 새로고침 복원을 확인했다. 각 사진·글꼴의 초기 로딩까지 포함한 모든 스크롤 좌표가 한 픽셀도 같다고 주장하지 않는다.
- **통과 — 문서:** 구매표 기본은 세오도라1부로 한정되어53개 다른 문맥 항목이 숨겨지고, 전체 비교에서는 해당 숨김이0이었다. 문서의 본문 체크 연결을 누르면 모달이 닫히고3부 해당 행동으로 이동했다. 병과 문서 닫기 전후 두 영역 위치0/0을 유지했다. 루트 편성 탭은 오른쪽 화살표로 레다로 이동하고 선택된 탭만 키보드 진입 순서0이 되는 것을 확인했다. 리브로 이름 클릭은 오른쪽 효과 카드로 이동했다.
- **통과 — 참고 보관:** 원본 캐릭터 도감을 iframe으로 열고 검색 상자에 리네를 입력해 원본의 전체 내용 검색 결과8명 표시를 확인했다. 인물 이름만 정확히 비교하는 검색이 아니라 원래 도감의 전체 내용 검색이다. 모든 보관 페이지의 필터를 각각 조작한 검증은 아니다.
- **통과 — 화면 크기:** 1920×1080에서 기본4열과 참고 숨김5열·현재25명 전체 표시, 카드 내용 잘림0을 확인했다.620×900은 두 열,390×844는 위아래 구역과 팀2열이며 바깥 가로 넘침·바깥 스크롤이 없었다. 실제 사용 주소의1396×1140 두 화면도 열었다. 화면 크기별 모든 문서·모든 편성 조합의 그림 검증을 뜻하지 않는다.
- **통과 — 글꼴·정적 표시:** `python tools/check_fonts.py`가 HTML283개·글꼴9개를 검사해 오류0. 기존 화면색 검사도 통과했다. Impeccable 정적 검사는 변경한 App.tsx/app.css에서 지적0. 핵심 글자/배경8쌍의 계산 대비는5.69 이상이다. 이는 모든 옛 내용의 모든 색 조합과 모든 보조기기의 실제 화면 검증을 대신하지 않는다.
- **통과 — 독립 검토:** 읽기 전용 검토에서 발견한 원시 HTML 체크 이벤트·문맥 필터·본문 체크 복귀·준비 도구 누락·보관 원본 기능·뒤로 가기·행동/인물 문맥 혼동을 수정했다. 재검토에서 해당 수정 범위 승인 판정을 받았다. 브라우저 검증은 위 범위로 한정한다.

## 수정 과정의 실패와 해결

Windows의 초기 생성 설정에서 TypeScript7이 삭제한baseUrl 옵션과, 기존 CSS의 여분 괄호를 발견했다. 앱 설정과 생성 CSS만 교정하고 다시 검사했다. 기존 CSS 원문은 바꾸지 않았다. Parcel이 한 차례 묶은 뒤 종료 중 비정상 종료했으며, 작업 수0 설정으로 다시 실행해 성공했다. 최종 빌드가 성공한 결과만 사용했다.

로컬 공략 서버의 종료·재시작 명령은 자동 승인 검토에서 정책상 차단됐다. 이유의 세부 항목은 제공되지 않았다. 프로세스를 다른 방법으로 종료하지 않았다. 기존 서버가 읽는 theme.js에서 두 개인화 주소만 새 묶음으로 연결해 해결했다. 실제 두 기존 주소에서 React 화면이 열리는 것을 확인했다. 서버가 다음에 정상 재시작되면 수정한 guide_server.py도 두 주소에 같은 묶음을 제공한다. 서버 재시작을 완료했다고 기록하지 않는다.

요청한 사용법 트윗은 웹 도구에서 열리지 않아 원문을 확인하지 못했다. 실제 작성 방식은 연결된 공식 스킬 원문과 공식 스크립트를 직접 확인하고 실행했다. 스킬과 이용 조건은 tools/web-artifacts-builder/에 보관했다.

## 기록과 한계

새 선호는 notes/knowledge/interface.md와 sources.md에 현재 프로젝트 범위로 기록했다. 게임 목표·편성·구매를 새로 승인받거나 실행 완료한 뜻이 아니다. 다른 브라우저·비공개 모드·브라우저 저장 차단에서 새 React 앱 전체를 실험하지 않았다. 외부 공개·원격 배포·다른 컴퓨터와의 표시 설정 동기화는 수행하지 않았다.
