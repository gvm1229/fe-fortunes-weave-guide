# 디자인 명세 구현 계획

정본: `docs/design-spec.md`. 새 색·장식·문구를 만들지 않는다. `archive/`와 원본 `content/data/`는 수정하지 않는다. TEMP/TMP는 저장소 `.tmp`를 사용한다.

1. 루트별 밝은/어두운 색 토큰, 실제 body 배경, 채운 버튼과 글자·간격 기준 적용. 커밋: `style: 루트별 명세 색상과 공통 표시 기준 적용`.
2. 군주 초상·원본 문장 자르기와 출처, 100dvh 대시보드 구현. 커밋: `feat: 문장과 군주 초상을 갖춘 대시보드 구현`.
3. 원본 HTML을 안전한 파생 표시 자료로 변환. 같은 묶음 얼굴 중복만 제거하고 모든 그림·위치 버튼 복원. 루트·부·장·묶음 비교를 verify에 연결. 커밋: `fix: 할 일 그림과 위치 버튼 복원 및 원본 대조 추가`.
4. 264px 옆 메뉴·820px 이하 본문·360px 보조 칸, 중간 화면 띠, 휴대폰 위·아래 탐색과 비고정 다음 행동 구현. 커밋: `feat: 명세에 맞춘 루트 화면과 보조 칸 구현`.
5. 인물·준비·재료 지도·720px 문서 시트·팀 출신 띠 적용. 커밋: `feat: 인물과 준비 재료 문서 팀 화면 명세 반영`.
6. build/lint/typecheck/verify와 실제 Chrome 화면 검사. 지정 네 크기와 1280×720, 두 테마, 대시보드·다섯 루트의 할 일·인물·준비 확인. 스크린샷과 수치 저장, 20MB 초과 이미지는 Git 제외. 커밋: `test: 화면 크기와 테마별 명세 검증 결과 저장`.

Git 쓰기가 거부되면 재시도 승인 요청 없이 구현을 계속하고 파일별 제안 커밋을 보고한다. 명세가 비어 있는 선택은 최소한으로 구현하고 최종 보고의 ‘질문’에 남긴다.

## 2026-11-13 재개

사용자 최신 지시를 적용한다. Git 명령·커밋·build는 실행하지 않으며 `.next`와 `archive/`는 변경하지 않는다. 기존 localhost:3000 개발 서버를 사용한다.

1. 위 계획의 파일과 관련 코드·JSON을 직접 읽어 잘린 쓰기, 구문 오류, 빠진 명세를 확인하고 복구한다.
2. 원본 저장소는 읽기만 하며 transfer와 파생 자료 생성을 다시 실행한다. 전후 해시로 실제 갱신 파일을 `docs/transfer-review.md`에 기록한다.
3. lint·typecheck·verify를 실행하고 원인을 고쳐 모두 통과시킨다.
4. §6의 네 크기·두 테마에서 첫 화면과 다섯 루트의 할 일·인물·준비를 검사한다. 재료·문서·팀과 저장 기능도 확인한다. PNG는 `docs/screens/`, 측정은 `docs/browser-results.json`에 저장한다. PNG 경로는 Git에서 제외한다.
5. 기존 커밋 1~4를 유지하고 추가 작업을 별도 그룹으로 제시한다. 명세에 없는 시각 선택과 모순은 ‘질문’에 기록한다.

## 재개 완료

파일 복구, 남은 화면 구현, 원본 4문서 재동기화, lint·typecheck·verify, 브라우저 236장면·9개 부 그림 대조·7개 동작 검사를 완료했다. 결과와 증명 한계·질문은 `docs/design-review.md`, 커밋 파일 묶음은 `docs/commit-groups.md`에 둔다. PNG 236개는 `docs/screens/`에서 Git 제외한다. 커밋은 0개이며 Git 명령을 실행하지 않았다.
