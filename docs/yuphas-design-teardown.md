## 1. 핵심 메커니즘

### 1.1 한 줄 요약

**"웹 문서"가 아니라 "게임 메뉴 화면 한 장"이다.** 화면 가운데에 그림으로 그린 액자(1800×970 그림 한 장)를 놓고, 모든 글자·표·단추를 그 액자 안의 정해진 자리에 **화면 폭에 비례하는 단위**로 붙인다. 페이지는 스크롤하지 않고, 액자 안의 칸만 스크롤한다. 이것이 저 사이트 느낌의 9할이다. 움직임·소리·커서 효과는 거의 없다.

### 1.2 구성 요소 다섯 개

1. **고정 무대** — `.wrapper { position: fixed; inset: 0; overflow: hidden; min-width: 800px }`. `body` 배경은 `black`. 문서 높이 = 화면 높이(1440×900에서 `scrollHeight` 900).
2. **그림 액자** — `section { background: url(background14.webp) 0 0 / 100% auto no-repeat; aspect-ratio: 1.85567 / 1 }` (= 1800/970). 안쪽 여백으로 내용 자리를 판다: 왼쪽 35%, 위 `8.7 × --vw`, 오른쪽 2.5%, 아래 `2.2 × --vw`.
3. **비례 단위 `--vw`** — `--vw: calc(max(100vw, 800px) / 100)`. 폭 800px 아래로는 더 줄지 않는다. 자리·크기를 `calc(22.2 * var(--vw))`처럼 쓴다. 그래서 액자 그림과 글자가 항상 같은 비율로 맞는다.
4. **맞춤 축소 스크립트** (`index.html` 인라인 `scaleToFit`, 전체 25줄)
   - `scale = min(1, 쓸 수 있는 폭 / .wrap 폭, 화면 높이 / (.wrap 높이 + 위 단추 자리))`
   - `.wrap`에 `transform: scale(S) translate(0, -50%)`, `top: 50%` → 세로 가운데.
   - `--scale`, `--cbSpace`, `--screenRatio`(화면 높이/폭)를 CSS 변수로 내보낸다.
   - 글자 보정: `.wrapper.style.fontSize = min(16, 15 / (scale × wrapper배율)) px` — 화면이 줄어 액자가 작아져도 글자는 덜 줄게 한다.
   - `window.resize`마다 다시 계산. 다른 라이브러리 없음.
5. **주소가 있는 겹침 창** — 큰 목록(인물·직업·무기·지도…)은 새 페이지가 아니라 **화면 전체를 덮는 창**(`#cmp`, `#lmp`)으로, 낱개 설명은 **가운데 작은 팝업**(`#idp`)으로 뜬다. 그런데 주소는 진짜로 바뀐다(`/characters/`, `/theodora/supports/`, `?item=royal-resolve`). `history.pushState/replaceState` + `popstate`로 뒤로 가기가 창 닫기가 된다. 뒤 화면은 `backdrop-filter: blur(4px)` + 검정 45~55%로 흐려진다.

## 3. 글꼴

### 3.1 쓰는 글꼴

- **단 하나**: `font-family: "Nocturne", serif` — 파일 `images/NocturneSerif-Regular.woff2` (52KB), 굵기 400 하나만 불러온다.
- `@font-face` 보정: `font-display: block; ascent-override: 95%; descent-override: 25%; line-gap-override: 0%`. 주석에 따르면 글꼴 파일 안의 세로 수치가 서로 달라 Chrome과 Firefox에서 글 높이가 달랐고, 이 값으로 대문자를 줄 상자 가운데에 맞췄다(대문자 높이 70%, 줄 높이 normal = 1.2em).
- **굵은 글은 가짜 굵기다.** 400 파일 하나뿐인데 `font-weight: bold/700`을 16곳에서 쓴다 → 브라우저가 획을 억지로 두껍게 그린다.
- **작은 대문자도 가짜일 가능성**: `font-variant: small-caps` 3곳. 글꼴에 진짜 작은 대문자가 들어 있는지는 확인하지 못했다(추정: 합성).
- 불러오기 화면 예비 글꼴: `16px/1.5 serif`.
- Nocturne Serif는 **상용 글꼴로 알고 있다(라이선스 직접 확인은 못 함).** 어느 쪽이든 그 사이트 서버의 파일을 가져다 쓰면 안 된다.

- 자료 JSON 8개 합 약 200KB 전송(data 62KB, locations 59KB, weapons 24KB, pictures 22KB, birdtime 20KB, ids 19KB, gifts 10KB, supports 4KB, blaze 3KB).

- 캐시: 파일마다 내용 해시(`?h=d81c997633`)를 붙여 바뀐 것만 다시 받음.
- 렌더: "입력이 바뀐 구역만 다시 그린다"(`renderIfChanged`, app.js 절 4 주석).
- 불러오기 순서: `<html class="loading">` → 본문 숨김 + 고리 → 자료 다 오면 `loaded`. 그동안 화면은 비어 있다.

## 9. 우리 사이트로 옮길 때

먼저 두 사이트의 성격 차이. 저쪽은 **찾아보는 사전**(화면 한 장에 꽉 채워 보기), 우리는 **따라 하며 체크하는 공략**(긴 목록을 내려가며 읽기, 휴대폰이 먼저, 글 18px 이상, 밝게·어둡게 둘 다). 그래서 **"고정 액자 + 비례 축소"라는 핵심 장치는 가져오지 않고**, 그 위에 얹힌 **겉모습 언어**(어두운 청록 판, 양피지색 글, 청동 선, 각진 모서리, 금속 구분선, 그림 틀, 빛나는 선택 표시)만 가져온다.

### 9.5 사용자에게 물어야 할 것(P04: 추천 표시)

사양에 없는 시각 결정이라 구현 전에 답이 필요하다.

1. **글꼴** — (A) Pretendard 유지, 제목만 한글 명조(Gowun Batang 또는 Noto Serif KR 700) **← 추천**: 읽기 쉬움과 게임 느낌을 둘 다 얻고 본문 18~20px 가독성을 지킨다. (B) 전부 명조. (C) 전부 Pretendard 유지(색·선·틀만 바꿈).
2. **모서리** — (A) 지금 값 유지(카드 16·단추 10·칩 8). (B) 전부 0px. (C) 2~4px로 줄여 각진 느낌만 **← 추천**: 저쪽의 각진 금속판 느낌을 내면서 누를 곳이 딱딱해 보이지 않는다.
3. **색 방향** — (A) 어두운 테마만 청록·양피지·청동으로 바꾸고 밝은 테마는 지금 유지 **← 추천**: 저쪽에 밝은 벌이 없어 밝은 쪽은 새로 지어내야 하기 때문. (B) §9.3대로 두 테마 모두 교체. (C) 색은 그대로, 선·틀·제목 모양만.
4. **틀 장식 수준** — (A) CSS 선만(이중 테두리 + 금속 구분선) **← 추천**: 그림 파일 없이, 4K에서도 선명. (B) 직접 그린 SVG 모서리 장식 추가. (C) 장식 없음.
5. **스포일러 가림**을 넣을지 — (A) 넣음(누르기 전에는 내용을 그리지 않음) **← 추천**. (B) 안 넣음(지금처럼 루트·부 분리로만).
6. **글 빛 효과** — (A) 큰 제목·현재 탭에만 **← 추천**. (B) 쓰지 않음.
