## 0. 구조와 방법 [확인]

| 항목 | 사실 |
|---|---|
| 화면의 할 일 글 | `content/derived/checklist.json`(= `content/source/react-content.json` HTML에서 파생). `content/display-overrides.json`의 `actions[id]`가 있으면 그 글이 나온다 |
| 분류 칩 | `content/data/playbook.json`의 `category`. 덮어쓰기 대상이 아니다 |
| 묶음 제목 | `overrides.groups[id]`가 있으면 그 글. 장 배치는 `react-content.json`의 원래 제목과 블록 순서로 정해진다 |

| 고정 수치 | 행동 1858, 체크 ID 2817(`verify.mjs` 21·22·54행, `transfer-manifest.json`), `oldBlockCounts` |

### 0.1 방법 다섯 가지

| 기호 | 쓰는 곳 | 방법 | 다시 만들 것 |
|---|---|---|---|
| **M1** | 행동 글·묶음 제목 바꾸기 | `display-overrides.json` `actions`/`groups` | 없음 |
| **M2** | 분류 칩 | `playbook.json` `category` | `refresh-manifest` |
| **M3** | 주의 글·준비 화면·골드 표 문장 | `playbook.json`/원천 자료 + `react-content.json` + (해당하면) `display-parity.json`에서 같은 문장을 똑같이 치환. 치환 전 횟수를 세고 기대와 다르면 멈춘다 | `derive:checklist` → `refresh-manifest` |
| **M4** | 새 행동·묶음 | 0.2 | `derive:checklist` → `refresh-manifest` + 수치 |
| **M5** | 묶음·행동 은퇴 | 0.3 | 같음 |

### 0.2 M4 절차

1. `playbook.json` `groups`에 추가. 행동 꼴 `{"id","category","text","inheritLegacy":false}`. 새 묶음은 `support-talks-cai-part1-20261112`(일반)·`recruit-all-theodora-nezha-20261112`(영입)를 본뜬다.
2. `react-content.json`: `stages[].blocks`에 `{id, html, title}` 삽입. HTML은 `support-talks-theodora-part1-20261112` 블록을 본뜬다. 행동 한 줄:
   `<li class="action-item" data-done="false"><input aria-label="글" data-inherit-legacy="false" data-parent-task="묶음ID" data-task-id="행동ID" disabled="" id="행동ID" type="checkbox"/><div class="action-label"><span class="action-category">분류</span><span class="action-text">글</span></div></li>`
   기존 묶음에 행동을 더할 때는 그 블록의 `</ol>` 앞에 넣는다. `allTaskIds`에 새 묶음·행동 ID를 넣는다.
3. `check-ids.json`에 같은 ID. `action-links.json`에 `"ID": "/루트/부/#ID"`.
4. `action-migration.json`은 손대지 않는다(최근 묶음도 없음).

### 0.3 M5 절차(은퇴)

1. `playbook.json`: 묶음을 `groups`에서 빼 `retiredGroups`로 옮기고 `"retiredReason":"2026-11-14 한 인물 한 루트 영입 결정으로 제외. 체크 이력은 보존."`을 붙인다. 묶음 안의 일부 행동만 뺄 때는 `retiredActions`로 옮기고 `parentTask`를 붙인다(기존 꼴과 같음).
2. `react-content.json`: 그 블록(또는 `<li>`)을 `stages[].blocks`에서 지운다. **`allTaskIds`와 `check-ids.json`에서는 지우지 않는다.**
3. `action-links.json`의 해당 줄은 지운다(현역 링크만 남김). `overrides.actions`에 은퇴 ID가 있으면 지운다(`verify.mjs` 17행은 현역 ID만 허용).
4. 장 배치 주의: 은퇴 블록이 그 장의 첫 블록이었으면 뒤 블록들의 장이 바뀔 수 있다. 은퇴 전후로 "장 제목 → 묶음 ID 목록"을 비교해 은퇴 묶음만 사라졌는지 본다.

## A. 한 인물 한 루트 영입

### A.1 비교 기준

`recruitment-gates.json`의 루트별 값으로 비교했다. 앞의 것이 같을 때만 다음을 본다.

1. 자동 합류(명성0·지원0, "조건 없음")가 가장 쉽다.
2. 명성이 낮은 쪽.
3. 추가 조건 등급이 낮은 쪽: 0 없음 < 1 골드 < 2 상점 물품·선택지 < 3 탐색 물품 < 4 의뢰·전투 < 5 외전 선행. 기한이 빡빡하면 +1(세오도라 12장 외전), 입수가 재배뿐이면 +2(카이 하르빈).
4. 골드가 적은 쪽.
5. 그 루트 인물 화면에서 본대·보완인 쪽.
6. 지원이 낮은 쪽(지원은 장 다시 하기로 공짜라 마지막).
7. 지금 대표 루트.

### C.2 검증

`npm run derive:checklist` → `node scripts/refresh-manifest.mjs` → `npm run verify` → `npm run lint` → `npm run typecheck`. `npm run build`는 하지 않는다.

`verify.mjs`에 더할 검사:

1. 표시 글(덮어쓰기 적용 뒤)의 `title`·`text`·`category`에 `선택 영입`, `영입을 생략`, `추가 영입하기로 골랐으면`, `우리가 확인하지 않았다`, `식당 식사를 반복`이 없다.
2. 네 1부 stage에 `feast-loop-<route>-part1-20261114`(행동 7개)가 있고 파생 체크리스트의 `12장`에 있다. `support-talks-<route>-part1-20261112`도 `12장`에 있다.
3. 2부 stage 표시 글에 `만찬을 반복`·`식사를 반복`이 없다.
4. `recruit-all-plan.json` `pairCoverage.routeRoster`의 각 인물이 그 루트 `team-<route>-recruit-audit--1` 표시 글에 있다(레다의 키릭·네이선 포함).
5. 한 인물 한 루트: `routeRoster`에서 두 루트 이상에 나오는 인물은 `duplicates` 목록에 있는 인물뿐이다.
6. 3부: 파생 체크리스트에서 `p3-feast-loop-20261114`가 `p3-merge`보다 앞에 있다.
7. 체크 보존: `checklist-seed.json`의 체크된 ID가 모두 `check-ids.json`에 있다.

직접 볼 것: 세오도라 12장 맨 위 근처에 만찬 묶음, 은퇴한 묶음이 화면에서 사라졌는지, 디트리히 9장에 밴디츠·카타냐, 카이 지원 묶음이 12장, 3부 2구간에서 재영입 → 만찬 → 융합 순서, 긴 합류 확인 글이 휴대폰 폭에서 넘치지 않는지.
