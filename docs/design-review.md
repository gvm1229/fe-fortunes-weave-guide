# 디자인 명세 v2 재개 검수

정본은 `docs/design-spec.md`다. 기존 `DESIGN.md`의 옛 색·글자·문장 설명보다 이 정본과 현재 사용자 지시가 우선한다. Git 명령 없이 파일과 Git 색인 파일을 읽어 변경 경로를 확인했다. Git 쓰기·커밋·build·`.next` 삭제·`archive/` 변경은 하지 않았다. 기존 `http://localhost:3000` 서버를 사용했다. TEMP/TMP는 저장소 `.tmp`다.

## 끊긴 쓰기와 복구

작업 파일 945개를 읽었다. JSON 74개, TypeScript 33개, JavaScript 10개에 잘린 구문은 없었다. TypeScript 검사로 준비 화면의 `hideGodPortraits` 속성 연결이 덜 끝난 부분을 찾아 복구했다. 브라우저에서 줄바꿈 태그의 잘못된 자식 처리와 표의 빈 글자·열 태그 처리도 고쳤다. 표의 게임 정보와 그림은 지우지 않았다.

기존 루트 전환 문구 수정 13개와 시작 전 안내 수정이 그림 복원 과정에서 우회되던 문제를 고쳤다. 그림·위치 버튼이 없는 이 문장 수정만 별도로 적용한다. 팀은 원본 `unit-readiness.json`의 `baseRoute`를 사용해 위 6px 띠를 칠한다. 공략 본문 폭, 신마다 32px 초상 한 번, 120×80 지도 썸네일과 지도 시트, 휴대폰 문서의 이름·값 목록을 확인했다.

## 실제 실행한 검사

호스트: Codex, Windows, Node.js 24.13.1과 설치된 Chrome 157.0.8103.51, Playwright. 원격 서버나 다른 운영체제에서 실행한 결과가 아니다. 최종 검사 중 원본 knowledge/interface.md의 추가 변경도 다시 동기화한 뒤 verify를 통과했다. 갱신 4파일과 현재 해시는 `docs/transfer-review.md`에 있다.

| 대상 | 실제 결과와 증명 범위 | 증명하지 않는 범위 |
|---|---|---|
| lint | `npm run lint` 통과. ESLint 오류·경고 없음 | 게임 사실 |
| 타입 | `npm run typecheck` 통과. 형식과 코드 연결 확인 | 모든 사용자 입력 |
| 이전·그림 | `npm run verify` 통과. 현재 원본 367파일 해시, 행동 1858개, 체크 ID 2817개, 문서 318개, 미디어 305개, 62개 루트·부·장과 각 묶음의 그림·위치 버튼 대조 | 게임 안에서 정보가 맞는지 새로 실측한 결과 |
| 브라우저 | `npm run test:browser` 통과. 236개 장면, 아래 9개 부의 실제 DOM 그림 대조, 동작 7개, 실행·HTML 구조 오류 0건. 재시도 0건 | 다른 브라우저·운영체제·배포 빌드 |
| 시각 검토 | PNG를 직접 확인. 휴대폰 첫 화면, 밝은 세오도라 할 일·준비, 어두운 레다 할 일, 태블릿 첫 화면 등에서 실제 배치 확인 | 사용자의 화면 배율·장시간 사용 피로 |
| Impeccable 검사 | 실행. 4px 왼쪽 띠 경고 2건은 명세 §1·§4가 요구하므로 유지 | 도구의 일반 취향 기준이 명세보다 우선한다는 뜻이 아님 |
| build | 현재 사용자 지시로 실행하지 않음. 개발 서버와 `.next`를 유지 | 배포 빌드·정적 내보내기 성공 |

측정 원자료는 `docs/browser-results.json`, 그림 대조는 `docs/image-parity.json`이다. PNG 236개는 `docs/screens/`에 있으며 `.gitignore`에서 제외한다. 개발 서버가 PNG 저장 때 다시 불러와지는 것을 막기 위해 `.tmp`에 찍고 브라우저 종료 뒤 복사한다.

## 측정

각 행은 밝게·어둡게를 모두 포함한다. 첫 화면과 다섯 루트의 할 일·인물·준비·재료·문서, 팀을 확인했다. 휴대폰에서는 지도·문서 시트도 확인했다.

| 크기 | 장면 | 가로 넘침 최대 | 최소 글자 | 첫 화면 세로 넘침 | 겹침 합계 | body 배경=명세 bg |
|---|---:|---:|---:|---:|---:|---:|
| 1440×900 | 54 | 0px | 18px | 0px | 0 | 54/54 |
| 1920×1080 | 54 | 0px | 18px | 0px | 0 | 54/54 |
| 375×812 | 72 | 0px | 18px | 0px | 0 | 72/72 |
| 768×1024 | 54 | 0px | 18px | 0px | 0 | 54/54 |
| 추가 1280×720 | 2 | 0px | 18px | 0px | 0 | 2/2 |

가로 넘침은 문서 전체 폭, 글자 크기는 표시되는 글자, 겹침은 탐색·도구 줄·장 제목·묶음 제목·인물·목록·시트 등 주요 배치의 형제 사각형 교차로 측정했다. 부모·자식의 포함 관계, 장식 문장, 고정 탭 아래로 지나가는 스크롤 내용은 겹침 결함으로 세지 않는다. 이것은 모든 그림 속 글자나 모든 임의의 요소 쌍까지 검사했다는 뜻은 아니다.

body의 실제 색은 카이 `#DCE7F8 / #0B1A33`, 세오도라 `#F6E7A8 / #231A06`, 디트리히 `#E9E7E2 / #0E0E10`, 레다 `#F7D9E3 / #2A0A17`, 3부 `#E5DBF6 / #170C2B`, 첫 화면·팀 `#EFEBE3 / #121116`이었다. 각각 밝게 / 어둡게이며 모든 장면에서 `--bg`와 일치했다.

## 원본 대비 그림과 위치 버튼

원본 합계에서 **같은 묶음의 같은 얼굴만** 한 번으로 줄였다. 다음 행동과 오른쪽 보조 칸의 추가 그림은 공략 원본 대조에서 제외한다. 접힌 장의 DOM도 센다. 화면에서 실제 읽을 수 없는 접힌 그림의 수와 현재 보이는 그림 수를 혼동하지 않는다.

| 레다 1부 | 1351 | 1348 / 1348 | 54 / 54 |

DOM 대조는 다섯 루트 1부·3부를 1440×900 밝게에서, 네 2부를 별도 검사에서 실행했다. 다른 크기·테마에서도 각 장면의 전체 그림 수·현재 보이는 그림의 로딩을 측정했지만, 원본과의 세부 종류별 DOM 대조를 모든 조합에서 반복하지는 않았다.

동작 검사는 체크 재로딩 보존, 잘못된 JSON 거부, 내보내기, 가져오기·개별 false 우선, 저장 실패 시 미반영, 문서 뒤로·읽던 위치 복원, 팀 세 편성 각각 25명이다. 실제 사용자 브라우저의 기록은 쓰지 않았다.

## 질문

- **명세 내부의 대비 충돌:** 밝은 디트리히 `#A8811F / #FFFFFF`는 3.61:1, 밝은 레다·3부 `#B08A26 / #FFFFFF`는 3.23:1이다. 18px 글자에서는 §1의 4.5:1에 못 미친다. 어느 전경색을 승인할지 필요하다. 새 색을 고르지 않고 지정 값을 유지했다.
- **공통 인물 띠:** 원본에 `baseRoute`가 없는 이스마르·3부 전용 인물은 공통 primary 띠로 남겼다. 특정 루트 출신을 추측하지 않았다. 이 공통 표시를 유지할지 지정이 필요하다.
- **3부 대표 초상:** 이전 구현의 카이 얼굴을 옆 메뉴·휴대폰 위 띠에서 유지했다. 3부 전용 대표 얼굴은 명세에 없다.
- **저장 오류의 빨간 면:** 빨강이라는 조건만 있고 정확한 토큰이 없어 `#B91C1C / #FFFFFF`를 썼다. 실패 때만 나타난다. 지정할 색이 있는지 남긴다.
- **공통 표의 빈 토큰:** 첫 화면·팀의 rail, surface-2, secondary, secondary-soft와 일부 전경은 기존 공통 값을 유지했다. 명세의 대시가 새 값을 뜻한다면 지정이 필요하다.

승인된 `rail-fg`는 다시 묻지 않는다. 밝게는 primary-fg, 어둡게는 text로 적용했다. 768~1199 첫 화면의 진행 행은 기존 4열을 유지하며 명세 간격 단계인 4px을 사용해 `1부`가 두 줄로 갈라지지 않게 했다.

## 지식 절차

범위는 user-root로 정했다. 명시된 전역 사용 모드 선호 하나의 기록을 1회 시도했으나 사용자 루트 접근이 Windows 샌드박스에서 거부됐다. 갱신 확인·지식 조회·기록·lint 모두 같은 접근 제한으로 실패했다. 정본 변경과 색인 영수증은 없으며, 전역 기록 성공으로 주장하지 않는다. 우회하거나 사용자 루트에 파일을 직접 만들지 않았다.
