# §8 디자인 검토 수정 계획

범위: `docs/design-spec.md` §8의 항목 1–6. 정해진 색·크기·문구·배치를 그대로 적용한다. 모호한 데이터 매핑은 숨기고 질문에 기록한다.

1. 저장 확인 표시를 진행 막대 오른쪽으로 옮기고, 할 일 머리 아래의 독립 안내를 제거한다. 골드 표의 안내는 유지한다.
2. 문장 속 병종·용어 링크를 높이 30px·18px 글자·좌우 8px 칩으로 바꾸고 문서 열기를 유지한다.
3. 저장 기록을 읽은 뒤 현재 장으로 즉시 이동한다. 완료 장은 48px 접힌 줄로 표시한다.
4. 이동 대상 행에 초점을 주고 2px accent 표시를 2초 유지한 뒤 사라지게 한다.
5. 옆 메뉴 하단의 테마와 첫 화면 버튼을 별도 줄에 두며 첫 화면은 아이콘과 전체 너비를 사용한다.
6. 인물 카드의 0 조건을 숨기고 확인된 시작·자동 합류 정보와 병종 등급을 읽는 말로 표시한다. 표의 접힌 설명을 온전한 줄 단위로 자른다.
7. 기존 개발 서버에서 lint·typecheck·verify와 Chrome 검사를 실행한다. 세오도라 1부 할 일·인물을 1440×900·375×812, 밝게·어둡게 확인하고 수치와 화면을 저장한다.

실행 제약: TEMP/TMP=`<repo>/.tmp`. Git 명령·커밋·build·`.next` 삭제·hive·전역 저장소 쓰기 없음. 검사는 별도 브라우저 문맥에서 수행하여 사용자의 체크 기록을 건드리지 않는다.

## 완료

항목 1–6 반영, lint·typecheck·verify 통과. Windows Chrome에서 요청한 8개 장면과 20개 동작을 확인했다. 병종 아이콘은 원본을 칩 안으로 옮겨 중복을 방지하고 원본 그림 수를 보존했다. 개발 서버 갱신과 겹쳐 중단된 화면 검사는 정적 검사가 끝난 뒤 단독으로 다시 실행해 통과했다.
